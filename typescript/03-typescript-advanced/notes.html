Pourquoi le TypeScript Avancé ?

Cette section introduit les concepts fondamentaux qui différencient un code TypeScript basique d'une architecture robuste. Dans de gros projets, copier-coller des interfaces similaires devient un cauchemar à maintenir. Le TypeScript avancé résout ce problème avec des types dynamiques, réutilisables et composables (comme des Lego).

Analyse : Utilité vs Complexité

Ce graphique illustre l'impact des différents outils avancés. Les Types Utilitaires offrent une valeur immense pour une complexité modérée.

🎯 L'objectif principal :

Écrire un code qui s'adapte automatiquement aux changements sans dupliquer les définitions de types.

Les Outils Fondamentaux

Explorez ici les briques de base de la composition de types. Vous découvrirez comment fusionner des entités, créer des tableaux à structure fixe et extraire dynamiquement les clés d'un objet. Cliquez sur les onglets ci-dessous pour explorer chaque concept.

Les Types d'Intersection

L'opérateur & fusionne plusieurs types. L'objet final doit posséder toutes les propriétés combinées.

type Volant = { ailes: number };
type Motorise = { moteur: boolean };

// L'objet doit avoir des ailes ET un moteur
type Avion = Volant & Motorise; 

const monAvion: Avion = {
    ailes: 2,
    moteur: true
};

Les Tuples

Un tableau dont on connaît la taille exacte et le type à chaque position spécifique. Idéal pour des coordonnées ou le retour de hooks comme `useState`.

// Position 0 = X, Position 1 = Y, Position 2 = Z
type Coordonnees3D = [number, number, number];

const maPosition: Coordonnees3D = [10, 20, 30];

// Erreur si on ajoute un 4ème élément ou du texte
// const erreur: Coordonnees3D = [1, 2, "Z"];

L'opérateur keyof

Génère automatiquement une Union (|) de toutes les clés d'un objet sous forme de chaînes de caractères.

type User = { 
    id: number; 
    username: string; 
    isAdmin: boolean; 
};

// Génère dynamiquement : "id" | "username" | "isAdmin"
type UserKeys = keyof User; 

function getProperty(key: UserKeys) {
    // Seules ces 3 chaînes sont acceptées
}

Génériques & Types Utilitaires

Cette section présente la véritable puissance de TypeScript : la capacité à écrire des types qui s'adaptent (Génériques) et la transformation de types existants (Utilitaires) sans les réécrire. Interagissez avec les boutons ci-dessous pour voir comment transformer un type de base BaseUser.

<T> Les Génériques

Des variables pour les types. Une "boîte" qui prendra sa forme à l'utilisation.

interface ApiResponse<T> {
  status: number;
  message: string;
  data: T; // Le type dynamique
}

const reponse: ApiResponse<number[]> = { 
  status: 200, 
  data: [1, 2, 3] 
};

Transformations interactives

Type de base

type BaseUser = { 
  id: string;
  name: string;
  age: number; 
};

Sélectionnez un utilitaire

Rend toutes les propriétés optionnelles (ajoute un ?). Idéal pour les mises à jour.

Résultat Généré

type UserUpdate = { id?: string; name?: string; age?: number; };

Déclarations et Packages (@types)

Cette section explique comment TypeScript gère les bibliothèques externes et sépare les contrats de types de la logique métier via les fichiers .d.ts. Vous y apprendrez que les types n'alourdissent jamais votre application finale.

🗂️

Fichiers .d.ts

Fichiers ne contenant QUE des types (pas de logique). Ils centralisent les contrats de l'application.

  • ✓ Totalement effacés à la compilation.
  • ✓ Zéro impact sur les performances.
  • ✓ Permet d'utiliser `import type { ... }`.
📦

Packages @types

Fournissent les types manquants pour les bibliothèques JS classiques (comme Express ou Node) via DefinitelyTyped.

npm install --save-dev @types/express

Cas Pratique : API BookShelf

Découvrez comment l'ensemble des concepts précédents s'articulent pour construire la couche de types d'une API de gestion de bibliothèque. Cette section structure le code du plus simple (alias) au plus complexe (services génériques). 

// 1. Alias de base
type EntityId = number | string;

type Timestamped = { createdAt: Date; updatedAt: Date; };
type HasId = { id: EntityId; };

// 2. Intersection : Composition
type Book = HasId & Timestamped & {
    title: string;
    author: string;
    isbn: string;
    isAvailable: boolean;
};

// 3. Tuple
type IsbnParts = [number, string, string];
// Création : on retire les champs générés par le serveur
type BookCreatePayload = Omit<Book, "id" | "createdAt" | "updatedAt">;

// Mise à jour : on réutilise la création en rendant tout optionnel
type BookUpdatePayload = Partial<BookCreatePayload>;

// Aperçu : on ne garde que l'essentiel
type BookPreview = Pick<Book, "id" | "title" | "author">;
// Signatures des requêtes réseau
function fetchBooks(): Promise<ApiResponse<Book[]>> {}
function createBook(payload: BookCreatePayload): Promise<ApiResponse<Book>> {}

// Utilitaires : K est restreint aux clés valides de T
function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {}

// Dictionnaire dynamique
function groupBy<T, K extends keyof T>(items: T[], key: K): Record<string, T[]> {}

Le Boss Final : EventEmitter Typé

Niveau Expert

L'objectif ultime est de créer une classe capable d'émettre des événements avec un typage dépendant. La donnée envoyée doit correspondre rigoureusement à l'événement déclaré, bloquant toute erreur avant même l'exécution du code.

🐉
// 1. Le dictionnaire d'événements strict
type BookEvents = {
  bookAdded: Book;
  bookRemoved: { id: EntityId };
};

// 2. La classe générique avec Typage Dépendant
class EventEmitter<Events extends Record<string, any>> {
  
  // K représente l'événement spécifique. 
  // Le payload EST le type Events[K].
  on<K extends keyof Events>(event: K, handler: (payload: Events[K]) => void) {}
  
  emit<K extends keyof Events>(event: K, payload: Events[K]) {}
}
💡

Pourquoi c'est si puissant ?

Si un développeur tape emitter.emit("bookAdded", "Dune"), TypeScript affichera immédiatement une erreur car "Dune" (texte) ne correspond pas à l'interface Book requise pour l'événement "bookAdded" dans le dictionnaire BookEvents.
